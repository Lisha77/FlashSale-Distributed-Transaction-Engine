22 orders from customers in different regions hit 6 items on 3 nodes. The scenario then forces lock contention, a partial-stock order, a cart spanning two nodes, a deadlock, a node crash and a coordinator crash. Everything the engine does appears below as it happens.

How to read this page

RouteThe router finds which node holds each item (query localization). 2PCTwo-phase commit: ask every node to PREPARE and vote, then the coordinator logs one decision (COMMIT or ABORT) and tells everyone. The coordinator's COMMIT log line is the commit point.

S2PLStrict two-phase locking: exclusive lock on an item until commit or abort. WALWrite-ahead log: undo and redo values are logged before stock changes. StockChanges to the stock numbers. Crashand RecoveryFailures, and how the log repairs them.

On each item tile: the big number is stock left, "sold" is committed sales, "held" is stock reserved by an order that has not committed yet. A red tile means sold + held + left no longer equals the starting stock, which is expected only while a crashed node has not recovered. Click a transaction row to follow just that order.

Cluster and live stock dots: purple = coordinator message, green = yes/commit, red = no/abort
